# Caesar∞ v2.0.0

`v2.0.0` 把 Caesar∞ 从首个端侧 Agent 基线推进为可持续使用的个人健康与多模型 Agent：健康数据改为只读 Mi Fitness 云端，DeepSeek 与 Google Gemini 进入统一 Provider，前台健康自动化、真机视觉与本地多模态链路完成收口。

## 发布内容

### Mi Fitness 健康与自动化

- 日卡片只采用小米官方日聚合；分钟数据只用于分时趋势，不再以分桶求和冒充全天总量。
- 接入步数、距离、活动消耗、活动时长、睡眠、心率、血氧、压力和运动记录等已确认指标；云端没有的数据直接隐藏，缺失与失败不显示为 `0`。
- 首页保留一张简洁的 `Mi Fitness` 健康卡，展示可用指标、来源、新鲜度与同步状态。
- 新增仅在 CampusAI 前台运行的 5 / 10 / 15 / 30 分钟健康任务。数据变化时生成 2–3 条短消息；未变化时只记录一条自然状态。
- 自动消息固定写入 `Caesar∞ 日常`，通知正文不添加“健康提醒”等类别前缀。
- CampusAI 只轮询小米云，不连接手环、不拉起 Mi Fitness，也不停止或抢占小米互联服务。

### DeepSeek、Gemini 与本地多模态

- DeepSeek 与 Google Gemini 共享同一 Agent 编排、流式事件、工具白名单、取消与最大工具轮次限制。
- 两个 Provider 都从账户实时模型目录中选择模型；各自保留选择，保存前再次在线验证，任务锁定后不会静默换模。
- Provider Key 使用 Android Keystore 加密，排除数据库、备份、日志、Git 与 APK。
- 健康数据默认不发送给模型；只有用户明确授权时才发送必要的当日汇总，不发送分钟序列、设备标识或小米认证信息。
- 本地 Qwen/MNN 图片链路保存持久化相对引用，覆盖相册、拍照、截图分享与多图；图片不会上传 DeepSeek 或 Gemini。
- SSE 读取与输出完整性守卫覆盖 UTF-8 跨分片、损坏 JSON、标点洪泛、控制字符、异常重复、断流与取消。

### SPECTRA 界面与稳定性

- 页面状态统一为单一全屏路由，修复 AI 返回首页后重复玻璃与迟到光学区域残留。
- 弹窗使用环境色自然模糊和半透明雾层，不再用纯白浮层或压黑遮罩。
- 新增绿色 `Aurora 森屿` 环境；SPECTRA 与 OpticalGlass 继续共享单一渲染器。
- 个人页新增年度节奏热力图，按完成记录、累计时长与目标快照着色。
- README 使用同一台 Xiaomi 15 Pro、同一版本的首页、AI 和个人页三联真机截图，不再以一张空会话竖图充当项目首屏。

### 运行时清理

- BandBridge / Gadgetbridge 已从产品客户端、服务、DI、设置、Manifest、测试和发布产物中移除。
- 历史逆向证据仍保留在 `docs/` 与 `work/`，但不参与应用运行。
- GitHub Release 只发布 Caesar∞ Android 主应用 APK 与校验文件。

## 下载与校验

正式发布应包含：

- `caesar-v2.0.0.apk`：Caesar∞ Android 主应用；
- `SHA256SUMS.txt`：APK 的 SHA-256。

请同时下载校验文件，并在安装前验证 APK 哈希。正式签名 APK 不能直接覆盖不同证书签名的 debug 安装；请先导出可迁移数据，再决定是否切换到正式签名版本。

V2 为了保留当前真机安装的数据与模型，明确沿用同一发布证书；因此可以直接覆盖现有 Caesar∞ 安装。证书 SHA-256 为 `D8:3C:2C:C6:86:A2:39:CD:2F:3A:A6:D5:CD:F6:F9:01:92:7F:93:77:16:A5:AE:47:E1:8B:B2:30:51:AA:BF:14`。后续版本必须继续使用这张证书，否则 Android 会拒绝覆盖升级。

## 已知边界

- 主要真机基线为 Xiaomi 15 Pro、Android 16、16 GB RAM。
- Mi Fitness 使用私有云端接口，长期兼容性、限流与新增指标仍需持续真机对照。
- 健康自动化只在 CampusAI 前台运行，不补发退到后台期间的整串任务。
- V2 没有通用网页搜索、任意 URL 浏览、视频理解或持续麦克风监听。
- Caesar∞ 不提供医疗诊断，不会把缺失健康数据伪造成测量结果。
- 当前仓库未附加开源许可证，默认保留所有权利。
