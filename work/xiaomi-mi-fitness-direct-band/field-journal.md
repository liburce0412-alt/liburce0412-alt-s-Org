# Anonymized field journal

## 2026-08-27 — Wearable SPP coexistence

### Reusable evidence

- E-003: pin the wearable implementation commit and confirm transport type before debugging authentication. A correct device key is irrelevant if the transport socket cannot remain owned.
- E-006: use read-only Android Bluetooth and service dumps to compare official-stack ownership with connection churn. Redact addresses, device serials, account IDs, and all key material before recording evidence.
- E-007: an `exported=true` provider is not necessarily a public API. Follow both manifest permissions and application-level caller/signature checks, and inspect region/feature gates before recommending a downstream integration.

### Core finding

For a Bluetooth Classic wearable exposing one RFCOMM/SPP service channel, two independent Android clients cannot be promised stable simultaneous ownership. Retry tuning can improve recovery without competition; it cannot create multi-client sharing.

### Reusable path

When the vendor stack must remain active, keep it as the sole radio owner and move the integration boundary downstream: supported system health exchange first, vendor cloud second, local privileged interfaces only when the caller genuinely satisfies their trust gate.

### Safe command pattern

```powershell
$adbPath = Join-Path $env:LOCALAPPDATA 'Android\Sdk\platform-tools\adb.exe'
$bt = & $adbPath shell dumpsys bluetooth_manager | Out-String
$events = @($bt -split "`r?`n" | Where-Object { $_ -match 'CLASSICAL-(CONNECTED|DISCONNECTED)' })
[pscustomobject]@{
  Connected = @($events | Where-Object { $_ -match 'CLASSICAL-CONNECTED' }).Count
  Disconnected = @($events | Where-Object { $_ -match 'CLASSICAL-DISCONNECTED' }).Count
}
```

This pattern intentionally reports counts only and does not persist raw Bluetooth identifiers.

## 2026-08-27 — Private health-cloud protocol validation

### Reusable evidence

- E-008: treat an OSS fixture generated by the same crypto implementation as a hypothesis, not an
  interoperability proof. Cross-check HTTP method, serialized model fields, sort order, and stream
  lifetime against the current app.
- A single RC4 object reused across sorted values is observably different from resetting RC4 for
  every value, even when both implementations can decrypt their own fixtures.
- Separate account exchange and API transport. Long-lived login cookies should be scoped to the
  account request; downstream health requests should contain only the short-lived cookie pair the
  official interceptor injects.

### Reusable path

Start with a deterministic, synthetic request/response vector and make write methods
unrepresentable. Add a fake transport for the complete auth state machine, including redirect host
validation and credential-scope assertions, before attempting one authorized live read.

## 2026-08-27 — In-process provider whitelist

### Reusable evidence

- E-009: a public `addWhiteList(package, signature)` method is not an integration API when it only
  mutates process memory and has no Binder, provider, component, configuration, or production
  caller that reaches it.

### Reusable path

Trace both the decision function and every write path to its trust state. Confirm package and
signing-certificate checks separately; an exported Android component does not let an ordinary
caller manufacture vendor trust.

## 2026-08-27 — Authorized cloud interoperability check

### Reusable evidence

- E-010: a single summary-only live request can validate the complete authentication and encrypted
  transport chain without retaining credentials, raw responses, or individual health records.
- A successful cloud read demonstrates removal of Bluetooth ownership contention; it does not by
  itself demonstrate long-duration reliability or band-to-cloud freshness.

### Reusable path

After offline vectors pass, validate one metric and one bounded window. Record only endpoint,
region, record count, pagination state, refresh state, and success/error class. Add paging,
server-time correction, bounded refresh, backoff, and schema adapters independently so each change
can be tested without broadening the read surface.
